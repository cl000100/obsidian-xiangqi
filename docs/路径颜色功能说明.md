# 路径颜色功能说明

## 功能概述

路径颜色功能允许用户在棋谱树的任意节点上添加颜色标记（红、绿、蓝、黄），系统会自动渲染节点之间的路径颜色，用于标识特定的变化序列或重要路径。

## 核心逻辑

### 1. 路径段划分

棋谱树被划分为多个**路径段**，每段路径独立处理：
- **起点**：根节点 或 分叉点
- **终点**：分叉点 或 叶子节点（没有子节点的终点）
- **分叉点**：同时属于上一段的终点和下一段的起点

```
示例：
        A
        |
        b
        |
        c
        |
        d (分叉点)
       / \
      e   f
      |   |
      g   h
```

路径段划分：
- 段 1: A → b → c → d
- 段 2: d → e → g
- 段 3: d → f → h

### 2. 标记点排序规则

每段路径内的标记点按**深度顺序**（step）排序，**不考虑颜色**，所有颜色的标记点混排。

```
示例：
路径：a → b → c → d → e → f
标记：c(红), d(绿), e(蓝)

排序后：c(第 1 个), d(第 2 个), e(第 3 个)
```

### 3. 配对规则

标记点按**顺序两两配对**：
- **第 1 个和第 2 个**配对
- **第 3 个和第 4 个**配对
- **第 5 个和第 6 个**配对
- 以此类推...

**颜色由每对的第一个（奇数位置）标记决定**

```
示例 1：2 个标记
标记：c(红), e(绿)
配对：(c → e)
颜色：红色（由 c 决定）
结果：c → e 显示红色

示例 2：4 个标记
标记：b(红), c(绿), d(蓝), e(黄)
配对：(b → c), (d → e)
颜色：红色（b 决定）, 蓝色（d 决定）
结果：b → c 红色，d → e 蓝色
```

### 4. 穿透规则

#### 情况 A：只有 1 个标记点
**向上穿透**到路径段的起点

```
示例：
路径段：a → b → c → d
标记：c(红) - 只有 1 个
结果：a → c 显示红色（向上穿透到起点）
```

#### 情况 B：偶数个标记点
按配对规则处理，无穿透

```
示例：
路径段：a → b → c → d → e → f
标记：b(红), d(绿), e(蓝), f(黄)
配对：(b → d), (e → f)
结果：b → d 红色，e → f 蓝色
```

#### 情况 C：3 个或以上奇数个标记点
前 (n-1) 个按配对处理，**最后一个向下穿透**到路径段终点

```
示例：
路径段：a → b → c → d → e → f → g
标记：b(红), c(绿), e(蓝), f(黄), g(红)
配对：(b → c), (e → f), (g 单独)
结果：
- b → c 红色（第 1 对）
- e → f 蓝色（第 2 对）
- g 向下穿透：g 之后的路径显示红色
```

### 5. 分叉点颜色归属

**分叉点的颜色只属于上一段路径**，下一段路径会忽略分叉点的颜色标记。

```
示例：
        A
        |
        b
        |
        c (红)
        |
        d (绿，分叉点)
       / \
      e   f
      |   |
      g   h(蓝)

处理结果：
- 段 1 (A→b→c→d)：
  - 标记点：c(红), d(绿)
  - 配对：(c → d)
  - 颜色：红色
  - 结果：c → d 红色

- 段 2 (d→e→g)：
  - 标记点：无（d 是分叉点，颜色被忽略）
  - 结果：无颜色

- 段 3 (d→f→h)：
  - 标记点：h(蓝) - 只有 1 个
  - 向上穿透：d → h 蓝色
  - 结果：d → f → h 蓝色
```

## 使用示例

### 示例 1：单段路径，成对标记
```
路径：a → b → c → d → e → f
标记：c(红), e(绿)

结果：c → e 显示红色
```

### 示例 2：单段路径，单个标记
```
路径：a → b → c → d
标记：c(红)

结果：a → c 显示红色（向上穿透）
```

### 示例 3：单段路径，奇数个标记
```
路径：a → b → c → d → e → f
标记：b(红), c(绿), e(蓝)

配对：(b → c), (e 单独)
结果：
- b → c 红色
- e 向下穿透：e → f 蓝色
```

### 示例 4：多段路径，分叉点有标记
```
        A
        |
        b
        |
        c (红)
        |
        d (绿，分叉点)
       / \
      e   f
      |   |
      g   h(蓝)

结果：
- 主干：c → d 红色
- 变招 1：无颜色
- 变招 2：d → h 蓝色（h 向上穿透）
```

### 示例 5：多段路径，互不干扰
```
        A
        |
        b (红)
        |
        c
        |
        d (分叉点)
       / \
      e   f(绿)
      |   |
      g   h

结果：
- 主干：A → b 红色（b 向上穿透）
- 变招 1：无颜色
- 变招 2：f → h 绿色（f 向上穿透）
```

## 支持的颜色

- **红色**：`flag-red` - `[红线]`
- **绿色**：`flag-green` - `[绿线]`
- **蓝色**：`flag-blue` - `[蓝线]`
- **黄色**：`flag-yellow` - `[黄线]`

## 操作方法

### 添加颜色
1. 选中要标记的节点
2. 点击工具栏的颜色按钮（红、绿、蓝、黄）
3. 节点上会添加对应的颜色标记

### 删除颜色
- **删除单个标记**：再次点击相同颜色按钮
- **清除所有颜色**：点击"清除"按钮

### 分叉点标记
- 可以在分叉点上设置颜色标记
- 分叉点的颜色只影响上一段路径
- 下一段路径从分叉点开始，但不包含分叉点的颜色

## 技术实现

### 数据结构
```typescript
interface ChessNode {
  id: string;
  step: number;          // 深度（第几步）
  comments: string[];    // 注释，包含 flag-red 等颜色标记
  children: ChessNode[];
  parentID?: string;
}
```

### 核心算法

1. **提取路径段** (`extractPathSegments`)
   - DFS 遍历树
   - 识别分叉点和叶子节点
   - 划分路径段

2. **计算边颜色** (`calculateAllEdgeColors`)
   - 对每段路径独立处理
   - 收集标记点（跳过非终点分叉点的颜色）
   - 按 step 排序
   - 配对处理
   - 处理穿透逻辑

3. **渲染边颜色** (`getEdgePathColor`)
   - 使用 `$derived` 缓存计算结果
   - 根据边 ID 查询颜色

### 修改的文件

1. **`src/lib/Tree/Tree.svelte`**
   - 重写路径颜色渲染逻辑
   - 实现按路径段独立统计
   - 实现分叉点颜色归属规则

2. **`src/modules/Tree/Actions.ts`**
   - 移除分叉点不能设置颜色的限制

3. **`src/utils/parse.ts`**
   - UBB 格式导出：`flag-red` → `[红线]`
   - UBB 格式导入：`[红线]` → `flag-red`

4. **`src/modules/Tree/parser.ts`**
   - 导入时解析路径颜色标记

## 注意事项

1. **标记顺序很重要**：标记点按深度顺序配对，不是按颜色配对
2. **分叉点颜色只影响上一段**：下一段会忽略分叉点的颜色
3. **奇数个标记的穿透**：最后一个标记会向下穿透到段终点
4. **跨段不配对**：不同路径段的标记点不会互相配对
5. **UBB 格式兼容**：导出导入会自动转换颜色标记格式
